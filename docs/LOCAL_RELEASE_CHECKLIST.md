# Single-user local release checklist

Scope agreed 2026-10-19: one Windows operator, loopback only, fictional or permission-cleared documents, no paid services or cloud resources. This is a bounded portfolio release, not enterprise production readiness. The bounded checklist is complete for the installed Windows environment, with the execution evidence and remaining limits below. This is not a fresh-machine or general reliability certification.

## Release gates, in order

- [x] **Startup and exposure:** follow [local setup](LOCAL_SETUP.md) from a clean source copy with the lockfile. Start the normal launcher/dev path, inspect its app listener with `Get-NetTCPConnection -State Listen` or `netstat -ano -p tcp`, and confirm loopback rather than `0.0.0.0`/`::`. Stop it afterward. The default config/CLI now explicitly use `127.0.0.1`; built preview already does. Do not override the host, enable tunnels or forward ports. Sign-in is one mock identity, not account security. No offline dependency-install guarantee is claimed.
- [x] **Source-file fidelity:** use one supported TXT, simple text PDF and simple body-paragraph DOCX fixture from existing synthetic fixtures. Compare uploaded original download bytes/hash to the input; inspect extracted text/order, version, page/paragraph/line references and important qualifications against the original. Use a table/column or scanned-PDF case to demonstrate an explicit limitation/rejection. Server validation does not independently re-extract PDF/DOCX; a structurally valid client-supplied extraction is not proof of original-file fidelity. Record supported layouts and mismatch outcomes; defer automatic server extraction unless observed failures demand it.
- [x] **Answer and retrieval demonstration:** demonstrate one correct answer with all qualifications and verifiable citations, one insufficient-evidence refusal, and one documented answerable-paraphrase false refusal. This rehearsal uses the bundled remote-work policy to demonstrate the known grammar limitation without replaying reserved inputs; [the four original final failures](ANSWERING_RESULTS.md) remain unchanged. Verify filters/version choice. Do not tune on or re-score the consumed final set as a new benchmark. Existing internal accuracy remains 16/20 and zero unsupported across 20 insufficient cases; no independent reliability claim.
- [x] **Comparison and review persistence:** exercise the dedicated comparison view in both directions, then inspect evidence from both conflict sources, save a clearly synthetic note, refresh/reopen and confirm persistence. Preserve unrelated notes. Confirm revision conflict messages do not silently overwrite edits. Conflict rules cover four narrow families and do not decide authority.
- [x] **Upload boundaries and errors:** run existing malformed, oversized, empty, duplicate and unsupported-file checks. Verify invalid metadata and extraction failures leave no misleading success state; library/note failures preserve the user's draft and provide a useful retry/sign-in instruction. Keep PDF/DOCX originals at most 5 MB and extracted text/TXT at most 512 KB. Body parsing precedes some limits; quotas are non-atomic and there is no rate limiter or malware scanning. Accept only trusted local files; do not represent these checks as hostile-upload hardening. Fix observed failures within existing flows.
- [x] **Backup/restore rehearsal:** stop all servers, including custom ports; back up the complete emulator state, verify hashes, and restore into an isolated copy/destination using the same app/dependency versions. Confirm an original download's bytes, metadata and saved note after restart; confirm existing destination state has a rollback copy. Never replace the only active library merely to demonstrate recovery. Backups contain private plaintext and must stay out of source/Git; retain a separate source checkpoint. Follow [backup instructions](LOCAL_SETUP.md#windows-launcher-and-local-backups).
- [x] **Regression and release record:** run existing Node tests, Python evaluator unit tests, typecheck/build, and relevant headed browser flows per [AGENTS.md](../AGENTS.md). Record exact commit/working-tree changes, tool versions, commands, outcomes and unresolved limits. Do not run a new final answering evaluation. Verify source exports exclude uploads, runtime state, secrets and backups while retaining licenses and evaluation evidence.

## Local relevance of security findings

- **Still relevant:** accidental network exposure, private backup handling, extraction/original mismatch, clear errors, bounded upload resources, note persistence and D1/R2 partial failures. Existing uploads clean up R2 best-effort; deletes span stores without a shared transaction. If a rehearsal reveals missing originals/orphans, repair that specific failure before release.
- **Lower priority for one trusted local operator:** hostile multi-account attacks, distributed rate limits and production identity infrastructure. Loopback is an exposure limit, not protection from another process or user on the same machine. Origin checks are partial; development sign-in is not real authentication.
- **Required before any future deployment:** the [preserved security blockers](DEPLOYMENT_SECURITY_REVIEW.md), including identity verification and log policy. No enterprise or shared-host security claim is allowed.

After these gates, prepare README, architecture walkthrough, demo recording and portfolio narrative in the order defined in [ROADMAP.md](../ROADMAP.md#3-local-portfolio-preparation-after-the-release-gate). Do not add features merely to broaden the stack.

## Release decision and final browser results

**The defined bounded single-user local release gates are met for this installed Windows environment.** No application features were added. The existing default-loopback correction and scope/security documentation are included with four focused browser tests. No production readiness, real multi-user security or independent accuracy claim is made.

- Main run: **23 passed / 1 failed** over 24 scenarios (10.4 minutes). All 22 existing scenarios passed. The new comparison test failed on an inaccurate label selector.
- First focused run: **3 passed / 1 failed**. Comparison clicked before initial client loading completed on cold startup. The final test uses accessible combobox roles and waits for the initial document response, as the existing browser helpers do. No application comparison code was changed.
- Final focused run: **4/4 passed** (1.4 minutes): forward/reverse comparison, both-version source navigation and exported direction; known answerable grammar false refusal; library 503/retry; empty/unsupported uploads and server-rejected invalid dates with draft preservation.
- Together, **26 distinct functional browser scenarios passed** across the main and corrected focused runs, plus the separate **1/1 restored-application rehearsal**. This was not a single uninterrupted 26-test green run. Main/focused failure artifacts remain retained.
- Headed Chromium used `slowMo: 800`, recorded videos and ten-second visible inspection pauses after each test. Artifacts: `work/local-release/app/outputs/release-browser`, `release-focused`, `release-focused-final`, and `restore-browser*`. They are private/ignored; inspect before sharing any recording.
- Coverage includes upload/search, exact source citations, correct answer/refusal, historical filtering, actual local WASM retrieval, keyword fallback, both-source conflict evidence, saved-note refresh, optimistic concurrency, load/save recovery, oversized/malformed files, mixed scanned-page warnings, keyboard focus and two emulated mobile widths. No physical-device test is claimed.
- After every rehearsal, the active library's **22 state-file sizes/hashes still matched the original backup**. The active library was never restored/replaced. Backups, restored state, expected rows and recordings remain excluded from Git/source exports.

Remaining limitations are explicit: dependency installation reused existing installed packages (the frozen-lockfile policy check passed, but fresh-machine/full reinstall remains unverified); the isolated restore used the same application/dependency versions; no power-loss/cross-version recovery guarantee; PDF/DOCX fidelity was sampled, not server-enforced; no OCR/complex-layout guarantee; internal answering results remain 16/20 with four false refusals and are not independent evaluation. Deployment/authentication/logging blockers in [the security review](DEPLOYMENT_SECURITY_REVIEW.md) remain open. No final answering inference, rescoring or tuning occurred.

Reproduction commands used: `node scripts/test.mjs`; `python -m unittest discover -s tests -p test_answer_evaluator.py`; `node node_modules/typescript/bin/tsc --noEmit`; parser/model preparation plus `node scripts/run-framework.mjs build`. Browser commands ran from the isolated app using `node node_modules/@playwright/test/cli.js test --grep-invert 'restored application' --output outputs/release-browser`, followed by `test local-release.spec.ts --output outputs/release-focused-final`. The private restore test compared backed-up database rows and hashes through real app endpoints, then checked a document and note in the UI. The backup helper and isolated source/dependency setup are described above; never point a restore rehearsal at the active library.
