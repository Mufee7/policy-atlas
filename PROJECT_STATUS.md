## Current conclusion

The app implements local version-aware ingestion, filtered retrieval, **bounded extractive answering**, comparison and human conflict review. The answerer uses explicit question/predicate rules and exact source quotations. It is not a generative model or general semantic entailment system.

Frozen implementation `5b6c60fe04101f3a1cc403c0b8b221f158abccbb` was evaluated once on 40 reserved cases: **16/20 correct answerable, 0/20 unsupported answers, 20/20 correct refusals**, and 96/96 valid quotation/citation references. Four answerable paraphrases were refused and remain failures. Initial sample targets were met; independently authored evaluation and general reliability are **not** established. No answerer/evaluator tuning followed final feedback. See [results and every failure](docs/ANSWERING_RESULTS.md).

## Distinguish the methods

| Term | Actual behavior |
|---|---|
| Extractive evidence | Retrieved source passages; a match alone does not establish an answer. |
| Extractive answer | [Bounded selector](lib/answering.ts) for direct limits, deadlines, approvals, eligibility and requirements; exact quotations, complete policy context, explicit decisions and verified citations. Deterministic rules, not trained answerability. |
| Generated answer | Newly composed language from a generative model. **Not implemented.** No generation model, prompts or generated-claim validator. |
| ML retrieval | Pretrained MiniLM embeddings/cosine inference in a browser worker. No project-specific training/fine-tuning. |
| Keyword retrieval | BM25 lexical ranking. Final answering evaluation used this mode; semantic answer accuracy was not separately evaluated. |
| Conflict detection | Four English pattern families, number/unit normalization and date/scope checks. Rule-based candidates with human review, not an ML contradiction classifier. |

## Evaluation independence audit

**Existing retrieval data is development-only.** [development.ts](lib/development.ts) imports 12 original labels from [samples](lib/samples.ts), adds 18 questions and six unsupported probes. [evaluate-semantic.mjs](scripts/evaluate-semantic.mjs) uses the same sample corpus. The [saved report](lib/retrieval-report.json) and public copy are the same measurement; [tests](tests/retrieval.test.ts) compare the live keyword baseline with saved metrics, not a fresh full semantic benchmark. These results already influenced method selection and cannot be renamed held-out.

Saved development ranking results: BM25 Recall@1 60%, MRR .650; semantic Recall@1 90%, MRR .939; hybrid Recall@1 70%, MRR .826. Semantic/hybrid returned candidates for all six unsupported probes. These are passage-ranking results, not answer accuracy or hallucination measurements.

**New answering experiment:** 40 development and 40 reserved cases (20 answerable/20 insufficient), with disjoint logical document families. Protocol/reservation hashes were committed at `51fa082` before implementation. Final rows/labels stayed in ignored `work/answering-reserved/`; only hashes/counts were inspected during development. After code freeze, prediction ran once and scoring ran separately in Python. Inputs, labels, predictions and report were published after consumption. A second invocation was blocked at the exclusive attempt marker before inference. Do not reuse these consumed cases for tuning plus a new final claim.

This is **internally reserved synthetic evaluation**, authored by the same coding agent as the implementation. Different families share substantial sentence templates. Four final questions used free-form wording outside the fixed grammar and all four were refused. It is not independently authored external evaluation or evidence of unseen pretrained-model data. Labels use annotated section IDs as a support proxy, separate from exact quotation integrity. Post-run inspection of 16 supporting quotations found the labelled facts; this is not independent human adjudication. [Full results/limits](docs/ANSWERING_RESULTS.md).
